# 桌面小组件 + 听歌足迹 · 设计规格（ui-ux-pro-max 评估）

评估口径与 `docs/SETTINGS-STYLE.md` 一致：**Minimal / Swiss**，靠底色与留白分层，不用阴影堆叠；两级文字（16sp 主 / 12.5sp 次）；强调色只用于「正在播放」「异常」「主操作」。

---

## A. 桌面小组件

### A1. 现有能力（可直接复用）

| 能力 | 位置 |
|---|---|
| 播放状态流（曲目、封面、进度、播放中） | `playback/PlayerController.kt` → `state` |
| 播放/暂停/上一首/下一首 | 同上 `togglePlayPause() / next() / previous()` |
| 封面位图与调色板 | `data/ArtworkLoader`、`playerViewModel.palette` |
| 服务已在跑（前台 Service） | `playback` 相关 Service |

### A2. 尺寸与布局（三档）

**4×2（主推，约 250×110 dp）**

```
┌──────────────────────────────┐
│ ┌────┐  歌名（16sp SemiBold） │
│ │封面│  歌手（12.5sp 次色）    │
│ └────┘  ▁▁▁▁▁▁▁▁▁▁ 进度 2dp  │
│         ⏮   ▶/⏸   ⏭         │
└──────────────────────────────┘
```

- 卡片圆角 **22 dp**（系统小组件常用半径，比 App 内 14 dp 更圆）；
- 内边距 14 dp；封面 56×56 dp、圆角 12 dp；
- 进度条高 2 dp、圆角 1 dp，轨道用 `label` 12% 不透明，填充用强调色；
- 三个按钮 44×44 dp 触控区，图标 22 dp。

**2×2（方形，约 110×110 dp）**：封面铺满 + 底部 40 dp 渐变 + 歌名一行 + 中央播放键。

**4×1（条形，约 250×56 dp）**：封面 40 dp + 歌名/歌手两行 + 播放键，无进度条。

### A3. 状态

| 状态 | 表现 |
|---|---|
| 未播放 | 封面位显示 `SfIcons.MusicNote` 占位（与 App 内一致）；文案「未在播放」；播放键置灰不可点 |
| 播放中 | 进度条走针；播放键为暂停图标 |
| 暂停 | 进度条静止；封面降低到 80% 亮度 |
| 加载中 | 进度条改为 30% 宽的往返扫光（1.2 s 循环，LinearEasing） |

### A4. 实现选型

- **Glance（`androidx.glance:glance-appwidget`）**：Compose 风格 DSL，跨版本一致，但需新依赖；
- 或 **RemoteViews + 手写 XML 布局**：零新依赖，样式控制精确，但代码量大。

建议 **Glance**：颜色/圆角/间距能用现有常量表达，后续与 App 内视觉一致的成本最低。

### A5. 更新策略（必须遵守，否则耗电）

- 播放状态变化 → `AppWidgetManager.notifyAppWidgetViewDataChanged` 或 Glance 的 `updateAll`，**节流 500 ms**；
- 进度条**不逐帧刷新**：只在暂停/切歌/±30 s 时更新，或用 `setChronometer` 交给系统绘制；
- 屏幕关闭 / 无播放时**不注册任何定时刷新**。

## B. 听歌足迹

### B1. 与现有页面的关系（重要，避免重复造页）

| 现有 | 内容 | 本次定位 |
|---|---|---|
| `PlaybackStatsScreen.kt`（370 行） | 本机统计：总时长、常听歌手/歌曲 | 保留，作为「累计」 |
| `ListenReportScreen.kt`（229 行） | 网易年度/月度报告（`/listen/data/report`） | 保留，作为「报告」 |
| **听歌足迹（新增）** | **按时间的足迹**：今天 / 本周 / 本月 的逐时段分布与热力图 | 新增第三个入口 |

三者共用数据层：本机 `PlaybackStatsStore`（264 行）+ `ListenReportApi`（`/listen/data/total`、`/listen/data/today/song`、`/listen/data/realtime/report`）。

### B2. 页面结构

```
听歌足迹                                  ← 32sp Bold / −0.6 字距
本周 · 12 小时 40 分                       ← 22sp，主数字用强调色

┌──────────────────────────────────┐
│  热力图（7 列 × 6 行 = 42 天）      │  ← 每格 14dp，圆角 3dp
│  ░░▓▓█░░▓▓ …                      │     透明度 0/25/45/65/85% 五档
└──────────────────────────────────┘
       周一 …周日（12.5sp 次色）

今天的时间线
┌──────────────────────────────────┐
│ 08:12  ♪ 歌名 · 歌手        4:31  │  ← 行 56dp，左侧时间 12.5sp
│ 09:03  ♪ 歌名 · 歌手        3:58  │
└──────────────────────────────────┘
```

- 顶部三段切换：**今天 / 本周 / 本月**（分段控件，不是 tab bar）；
- 热力图每格代表一天，颜色深浅 = 当天播放时长（相对本期最大值分五档）；
- 时间线按小时聚合：同一小时内连续播放的曲目折叠成一行「09:00–10:00 · 8 首」。

### B3. 交互与可达性

- 热力图格子 14 dp 视觉，但**点击热区 44×44 dp**（不可见扩展）；
- 点某一天 → 下方时间线切换到那一天（不新开页）；
- 空态：本周无数据时显示「这周还没听歌」+ 一个「去听」按钮（强调色文本）；
- 长按时间线某行 → 复制「歌名 - 歌手」。

### B4. 数据来源（优先级从高到低）

1. **本机**：`PlaybackStatsStore` 已有逐次播放记录 → 时间线、热力图都从这里算，离线可用；
2. **网易**：`/listen/data/total`（总时长）、`/listen/data/today/song`（今日歌曲）→ 仅用于顶部「累计」数字，失败就隐藏，不阻塞页面。

---

## C. 实施顺序

1. **听歌足迹**（纯 Compose + 已有数据，风险低，1 轮可完成）
2. **小组件**（需新增 Glance 依赖 + Manifest 声明 + 三档布局，2~3 轮）

理由：足迹复用现有 store，不引入依赖；小组件要动 manifest 与系统集成，适合单独一轮验证。
